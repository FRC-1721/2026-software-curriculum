04

Anticipated questions

Why an enum instead of numbers?
Names read like English and the compiler blocks states that don't exist. RobotState.SCORING can't be mistyped as 3.
My state never changes.
Usually = used where == was meant, or a case missing its break (fall-through). Check both.
What's driver::getAButton?
A method reference — shorthand for () -> driver.getAButton(). It's a BooleanSupplier the machine calls each loop.
Why check STOP before the switch?
STOP should win from any state; handling it first keeps that rule in one place.
Do real robots use this?
Yes — subsystems track state this way, and Week 4's command framework is built on exactly these pieces.

1Name the states4 min

Open RobotState.java — an enum, a fixed list of names:

public enum RobotState {
  IDLE("Idle"), INTAKING("Intaking"), SCORING("Scoring");
  // the label is a friendly name — enums can hold data!
}
Why an enumThe code says RobotState.SCORING, not a mystery number — and you can't mistype a state that doesn't exist.
2Build the transitions10 min

In Superstructure.java, complete the switch to match the diagram:

if (stopButton) { state = RobotState.IDLE; return state; }  // STOP wins
switch (state) {
  case IDLE:     if (intakeButton) state = RobotState.INTAKING; break;
  case INTAKING: if (scoreButton)  state = RobotState.SCORING;  break;
  case SCORING:  if (scoreButton)  state = RobotState.IDLE;     break;
  default: break;
}
Two classic bugs== compares, = assigns — don't mix them. Every case needs a break, or it falls through.
3Run the tests4 min
./gradlew test        # Windows: gradlew test
✅ Checkpoint 1All transition tests pass. A failure names the exact transition that's wrong — fix that one rule.
4Drive it with buttons8 min

Robot.java wires the buttons as lambdas — the same shape as Week 4's bindings:

superstructure.update(
    driver::getAButton,   // A = intake
    driver::getBButton,   // B = score
    driver::getYButton);  // Y = stop

Simulate → Teleoperated → press A → -> Intaking, B → -> Scoring, B again → -> Idle, Y anytime → -> Idle.

✅ Checkpoint 2The printed state follows the diagram as you press buttons.
