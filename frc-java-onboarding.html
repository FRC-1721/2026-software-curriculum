FRC · Java · WPILib 2026
12-Week Onboarding Program · Software

From First Commit
to a Robot That Drives Itself

A twelve-hour classroom thread that takes students new to FRC from “what is this build system” to contributing integrated, reviewed Java on a real swerve robot — teleop, autonomous, telemetry, and log-driven debugging. Sim-first so every student stays hands-on; the real robot is the reward.

12 weeks 1 hr / week Java only WPILib 2026 Mixed experience Sim + real swerve
01

How this plan is built

The goal in twelve hours isn’t expertise — it’s fluency in the workflow: clone the repo, build, deploy or simulate, read the telemetry, find the problem in the data, fix it. Every Java concept is taught because a subsystem needs it, never in the abstract. Three constraints shape every week below.

One hour is short
Each session is scoped tight with a fixed template and a short homework bridge. Expect real depth to land in build-season lab time; the 12 weeks are the backbone.
The group is mixed
Every week has a core path everyone must reach and a stretch path for students who already know Java. Experienced↔new pairing is the default seating.
Sim first, robot as reward
Build and validate in simulation; deploy to last year’s swerve bot at three milestones (Weeks 6, 11, 12). Sim keeps 100% of students working even when the robot is busy.

04

The twelve weeks

Phase A · Weeks 1–4

Foundations

Get everyone tooled up, comfortable in Java, and able to build a working subsystem in simulation.

Week
01
Environment, tooling & “Hello, Robot”
Objective: everyone can create a project, build it, run it in simulation, and commit to Git.
Concepts
Where FRC code runs (roboRIO, Driver Station); the WPILib VS Code environment; GradleRIO build; project anatomy (Main.java, Robot.java); the robot lifecycle; Git basics.
Core lab
New project from a template → build → run in the Simulation GUI → print in teleopPeriodic → first commit.
Stretch
Set up the shared repo, write a .gitignore, branch, and open a first pull request.
Deliverable
Project builds & runs in sim on the student’s own laptop; first commit pushed.
Homework
Confirm the WPILib 2026 install on your personal laptop; read “Zero to Robot.”
Mentor
Pre-install on shared laptops; create the GitHub org/repo; keep a fallback laptop ready. Watch for version mismatch and un-imported 2025 projects.
Week
02
Java for FRC, part 1 — values, methods, objects
Objective: read and write basic Java grounded in real robot values.
Concepts
Primitives (why robot values are usually double); variables; methods; classes vs. objects, new, fields; access modifiers; why mixing units bites you.
Core lab
Write a small helper class (deadband, clamp, rotations→meters) and call it; read and print a joystick axis.
Stretch
Write a JUnit test for the math class; explore record and enum.
Deliverable
A committed, working helper class the student wrote.
Homework
3–4 short Java exercises (handout).
Week
03
Java for FRC, part 2 — control flow, enums, interfaces & lambdas
Objective: control program flow and meet the OOP pieces command-based relies on.
Concepts
Conditionals, boolean logic, loops; enum for robot states; inheritance & interfaces (why a subsystem extends a base class); lambdas & method references; Supplier/Consumer.
Core lab
Model a 3-state machine (IDLE/INTAKING/SCORING) and switch states from simulated button presses.
Stretch
Refactor the logic behind an interface; use DoubleSupplier the way commands do.
Deliverable
A committed state-machine class driven by input.
Homework
Implement one more state transition on your own.
Week
04
The command-based framework
Objective: understand subsystems, commands & the scheduler; build a controllable subsystem in sim.
Concepts
SubsystemBase; Command & requirements; the scheduler (use CommandScheduler.getInstance().schedule(...) — Command.schedule() is deprecated in 2026); default commands; RobotContainer & Trigger/CommandXboxController bindings; inline commands & simple compositions.
Core lab
Fill in a subsystem skeleton so a button spins it up and a default command holds it at rest; run in sim and watch the scheduler.
Stretch
Compose two commands into a sequence; add a Trigger that fires on a sensor condition.
Gate ✓
Student can independently create a subsystem + command and drive it in simulation.
Phase B · Weeks 5–8

Real robot programming

Motors, the swerve drivetrain, sensors, closed-loop control, and proper telemetry — culminating in driving the real robot.

Week
05
Motors, vendordeps & the swerve drivetrain
Objective: understand how motors are controlled and how a swerve drivetrain is structured.
Concepts
Brushless motors & controllers (CTRE TalonFX/Phoenix 6, REV Spark/REVLib); installing vendordeps; the CAN bus; gear ratios & units; what swerve is (module = drive + steer + absolute encoder); kinematics at a high level.
Core lab
Install the vendordeps; drive the simulated swerve bot with a controller; identify the four modules in code.
Stretch
Read one module’s code end-to-end; explain field-relative vs. robot-relative.
Deliverable
Simulated swerve driving under student control.
Mentor
Lock the swerve stack decision and align the repo before this session.
Week
06
Driving the real robot★ Milestone
Objective: safely deploy to and drive last year’s swerve bot.
Concepts
CommandXboxController; joystick scaling & deadbands; slew-rate limiting; field- vs. robot-relative teleop; safety (enable/disable, e-stop, brownout, space & spotters); the drive default command; deploying via Driver Station.
Core lab
Deploy the team’s code to the real bot; drive field-relative; tune deadband and max speed. Rotate driver / spotter / observer roles.
Stretch
Implement slew-rate limiting and a “slow mode” speed scale.
Deliverable
The team drives the real robot under their own code — major milestone.
Mentor
Safety briefing, bumpers on, clear space, one spotter per run. Sim is the fallback for students away from the bot.
Week
07
Sensors & feedback — encoders, gyro, closed-loop basics
Objective: read sensors and make a mechanism go to a setpoint.
Concepts
Encoders (position & velocity); gyro/IMU & heading; odometry (concept only); open vs. closed loop; PID starting with P; feedforward for velocity; setpoints.
Core lab
Read and display encoder + gyro values; add P control to a test mechanism so it holds/reaches a setpoint.
Stretch
Add I and D and a simple feedforward; mention SysId as the proper way to find gains.
Deliverable
A mechanism that reaches a setpoint under closed-loop control.
Homework
Predict what raising/lowering P will do; note it, then test next session.
Week
08
Telemetry done right — Epilogue + AdvantageScope
Objective: instrument the robot with modern telemetry and view it live.
Concepts
NetworkTables (the pipe); Epilogue @Logged annotations (the modern 2026 way); why we skip Shuffleboard/SmartDashboard; connecting AdvantageScope to sim and the real robot; live graphs, tables, and the 2D/3D field.
Core lab
Add @Logged to the drivetrain + one mechanism; open AdvantageScope; build and save a layout showing drive speed, a sensor value, and robot pose on the field.
Stretch
Log a custom struct/pose; add a 3D mechanism visualization.
Gate ✓
Student can add telemetry and read live data in AdvantageScope.
Phase C · Weeks 9–12

Telemetry-driven development & autonomy

Analyze logs, add AdvantageKit logging + replay, program autonomous, and integrate everything into one working robot.

Week
09
AdvantageScope deep dive — logs, scrubbing & debugging
Objective: use recorded logs to diagnose robot behavior after the fact.
Concepts
On-robot logging (DataLogManager, .wpilog); downloading logs; timeline scrubbing; overlaying signals; spotting real problems (a module not tracking, current spikes, loop overruns); exporting.
Core lab
Enable logging, generate a log by driving, download it, open it in AdvantageScope, and investigate a fault.
Stretch
Correlate multiple signals to explain a behavior; find a loop-overrun event.
Deliverable
A short written “log analysis” — what the data shows and why.
Homework
Bring one question you’d want the logs to answer during a real match.
Week
10
AdvantageKit — logging & deterministic replay
Objective: understand what AdvantageKit adds and get logging + replay working. (Basics — not a full IO rewrite.)
Concepts
What AdvantageKit is and why (deterministic replay); the “logged robot” idea; inputs vs. outputs conceptually; the replay workflow — replay a real run offline and add new logged values retroactively. Set up via a template or existing-project integration.
Core lab
On a copy of the project, enable AdvantageKit logging, record a run, then replay it offline and reproduce the robot’s state.
Stretch
Implement a minimal IO interface for one subsystem — a first taste of the full pattern (optional).
Deliverable
A successful replay of a logged run.
Mentor
Keep ambition to logging + replay; the full IO architecture is a post-course topic.
Week
11
Autonomous — command groups, odometry & PathPlanner★ Milestone
Objective: make the robot act on its own.
Concepts
The autonomous period; command groups for auto; odometry-based movement; PathPlanner (paths, autos, event markers); selecting an auto with SendableChooser.
Core lab
Build a simple auto (drive + one action) as a command group; create a PathPlanner path; run it in sim, then on the real swerve bot; verify path vs. actual pose in AdvantageScope.
Stretch
Add event markers that trigger a mechanism mid-path; tune pose accuracy.
Deliverable
A working autonomous routine, validated in sim and on the real robot.
Mentor
Field space + safety for real auto runs; a known-good starting pose.
Week
12
Capstone integration & showcase★ Milestone
Objective: combine teleop + auto + telemetry + logging into one working robot, and present it.
Concepts
Integration; what “competition-ready” code looks like; the Git code-review / PR workflow; the season roadmap.
Core lab
Complete a small integrated challenge on the real swerve bot — drive, run a scored auto, full telemetry + logging on; peer code review via pull requests.
Stretch
Experienced students lead the code review and own the PR merge.
Gate ✓
Capstone demo + team retrospective + a clean repo on main.
Beyond
Roadmap: vision & AprilTags · the full AdvantageKit IO-layer pattern · SysId characterization · advanced auto & state-space control.

06

Risks & contingencies

60 minutes is tight
Strict session template, provided skeleton code, homework bridges, and optional open-lab time in build season.
Real robot unavailable
Every real-robot week has a sim fallback — no session is lost to a hardware fault or a busy mechanical team.
Mixed pace pulls apart
The core/stretch split plus experienced↔new pairing keeps both ends engaged.
Swerve stack uncertainty
Resolved by the Week-5 mentor decision; align the repo before Week 5.
Install friction
Pre-installed shared laptops as backup; Week-1 homework surfaces problems early.
Absences break continuity
The repo is the source of truth; a student who misses a week pulls the reference branch and catches up.
