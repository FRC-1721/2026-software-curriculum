03

Anticipated questions

Why double and not int?
Robot values are rarely whole numbers — a stick at 0.42, a distance of 1.37 m. double holds decimals.
Why not new RobotMath()?
Every method is static — it belongs to the class, not an object. Call them by name: RobotMath.clamp(...).
My test fails but the code looks right.
Read the failure — JUnit prints expected vs. actual. Usually a sign or order-of-operations slip. Print the inputs if unsure.
./gradlew isn't found.
On Windows it's gradlew test. Make sure the terminal is in the project folder.
How is this different from WPILib's deadband?
Almost not at all — WPILib ships MathUtil.applyDeadband. We write our own to learn how it works.

1Read a method4 min
public static double deadband(double value, double deadband) {
  if (Math.abs(value) > deadband) {
    if (value > 0.0) return (value - deadband) / (1.0 - deadband);
    else              return (value + deadband) / (1.0 - deadband);
  }
  return 0.0;
}
Why "static"RobotMath is a utility class — call methods on the name: RobotMath.deadband(0.5, 0.1). Never new RobotMath().
2Write clamp7 min

Keep a value inside a range: clamp(5,0,1)→1, clamp(-5,0,1)→0, clamp(0.5,0,1)→0.5.

HintMath.min(a,b) is the smaller, Math.max(a,b) the larger. Nest them.
3Write rotationsToMeters5 min

One rotation rolls a distance of π × diameter. So rotationsToMeters(1.0, 0.1016) ≈ 0.319 (a 4-inch wheel). Hint: Math.PI.
