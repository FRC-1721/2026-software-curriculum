01

Before class — prep checklist

Week 1 lives or dies on install friction
  • WPILib 2026 pre-installed on every shared laptop — the offline installer is large; don’t rely on room Wi-Fi for 15 simultaneous downloads.
  • GitHub org + team repo created, with a week-01-reference branch holding the finished project (from the starter pack).
  • One fallback laptop fully working, so a student with a broken environment pairs on it rather than losing the hour.
  • Projector tested with VS Code at ~18–20pt editor font.
  • Student lab handout printed or on-screen.
  • GitHub access decided — recommended: everyone gets write access and pushes to a personal branch wk1/<name>.
The #1 failure modeA student’s laptop has an old WPILib, a JDK conflict, or an un-imported 2025 project. Budget for it — that’s what the fallback laptop and experienced-student pairing are for.

03

Minute-by-minute

10 · 10 · 35 · 5
0:00–0:10Warm-up & framing

Say: “Over 12 weeks you’ll go from an empty project to code that drives a real swerve robot and runs on its own. Today we set up your tools and prove the whole loop works. By the end of the hour, code you wrote will be running.”

Do
  • Show of hands: who’s coded before? Any Java? Seat one experienced student with one new student per station.
  • Point at the board diagram — code lives in three places: your editor, the robot, GitHub. Today a simulator stands in for the robot.
  • State the one deliverable plainly: build, simulate, print something you wrote, commit it.
PacingDon’t over-explain. Ten minutes, then hands on keyboards.
0:10–0:20Concept + live demo

Project your screen and narrate every click — beginners lose you when the mouse moves silently. Four things they need:

  1. What FRC code is — a Java program on a fixed rhythm. Introduce the lifecycle and write on the board: Init = once, Periodic = ~50×/second.
  2. The tools — VS Code (editor), the WPILib extension (the red “W”), GradleRIO (the build system; untouched today).
  3. Project anatomy — Robot.java (where you live), Main.java (don’t touch), build.gradle (leave alone), .gitignore / vendordeps/ (one line each).
  4. Simulation — run all of it with no robot; a window pretends to be the robot + Driver Station.
Live demo (~5 min)
  • Create a project: Template → java → Timed Robot, name hello-robot, generate.
  • In teleopInit() add:
System.out.println("Hello, Robot! — Coach demo");
  • Simulate → check Sim GUI → set Robot State to Teleoperated → the message appears.
  • The teachable twist: move the same line into teleopPeriodic(), re-simulate, and let it flood the console. “That’s the 50-times-a-second loop.” Then move it back.
Why this demo mattersIt plants the single most important mental model of the whole course — the periodic loop — in a way students see, not just hear.
0:20–0:55Hands-on lab — the core of the hour

Students work from the Student Lab tab. You and co-mentors float and clear each checkpoint.

Core path — everyone must reach
  • Verify install → create Timed Robot project → build (BUILD SUCCESSFUL) → add their own println → simulate & see it → first commit pushed to wk1/<name>.
Verify per pair (physically confirm)
  • ✅ BUILD SUCCESSFUL appeared · ✅ their own message printed · ✅ git log shows the commit.
Stretch — for the fast movers
  • Open a pull request from wk1/<name> into main.
  • Print a once-per-second countdown in teleopPeriodic using a counter (loop made useful, not noisy).
  • Explore the Sim GUI (joysticks, NetworkTables) — then help a neighbor. Praise this openly; it’s how mixed groups work.
Floating priorities, in order
  1. Won’t generate or build — usually JDK/version. Fall back to the shared laptop past ~5 min.
  2. Won’t simulate — usually the Sim GUI extension unchecked, or state not set to Teleoperated.
  3. Git — expect this to eat time (auth, first git config, “nothing to commit”).
0:55–1:00Commit, wrap & homework
  • Confirm every student pushed at least one commit; note anyone who didn’t for follow-up.
  • Recap out loud: “Editor → build → simulate → commit. Init once, Periodic fifty times a second. Next week: actual Java.”
Homework to assign
  • Get WPILib 2026 working on your personal laptop (if you used a shared one).
  • Read WPILib “Zero to Robot,” steps 1–4.
  • Optional: change your message and push a second commit.
04

Anticipated student questions

Why Java and not Python or C++?
Our whole codebase and last year’s robot are in Java — you’ll read real team code from day one, and it’s the most widely supported FRC language.
Do I need the robot to test my code?
Not this week — the simulator does it. We deploy to last year’s swerve bot in Week 6.
My build failed / it’s red everywhere.
Almost always one of: wrong WPILib version, a JDK conflict, or an un-imported 2025 project. Check the version first; fall back to the shared laptop if it drags past ~5 min.
What’s the difference between Init and Periodic?
teleopInit runs once, the instant Teleop starts. teleopPeriodic runs ~every 20 ms — 50×/second — the whole time you’re in Teleop. That loop is the heartbeat of robot code.
Why is my print statement showing thousands of times?
You put it in a Periodic method — it runs 50×/second. Put one-time messages in an Init method.
Do I have to use Git? It’s confusing.
Yes — it’s how the team shares code and recovers when something breaks. Clunky for a week, then second nature. Today, just get one commit pushed.

0Check your tools2 min

Open VS Code. Look top-right for the WPILib icon — a red hexagon with a “W”. See it? You’re installed. Don’t see it? Tell a mentor now and pair on a ready laptop.

TipPress Ctrl/Cmd+Shift+P and type WPILib to see every WPILib command. The “W” icon does the same thing.
1Create your project5 min

Command palette → WPILib: Create a new project. Fill in:

  • Project type: Template · Language: java · Base: Timed Robot
  • Project name: hello-robot · Team number: ask your mentor

Click Generate Project → Yes (Current Window).

✅ Checkpoint 1The left sidebar shows folders like src and gradle, and files like build.gradle.
2Look around3 min

Open src/main/java/frc/robot/Robot.java — where you’ll live all course. Find these two methods:

@Override
public void teleopInit() {
  // runs ONCE when Teleop mode starts
}

@Override
public void teleopPeriodic() {
  // runs about 50 TIMES PER SECOND while in Teleop
}
The most important idea in robot codeInit methods run once. Periodic methods run ~50 times a second — the robot’s heartbeat. Peek at Main.java if you like, but don’t change it.
3Build it3 min

Command palette → WPILib: Build Robot Code. Watch the terminal for:

BUILD SUCCESSFUL
✅ Checkpoint 2You see BUILD SUCCESSFUL. If it says BUILD FAILED, read the first red line and call a mentor.
4Make it say hello5 min

Inside teleopInit(), add one line with your own name, then save (Ctrl/Cmd+S):

@Override
public void teleopInit() {
  System.out.println("Hello from Priya!");   // ← YOUR name
}
5Run it in the simulator6 min
  • Command palette → WPILib: Simulate Robot Code.
  • If asked, check Sim GUI → OK. A Simulation window opens — your pretend robot + Driver Station.
  • In the Robot State panel, click Teleoperated.
  • Look at the VS Code terminal — your message appears.
🎉 Checkpoint 3Your message printed. You just ran code you wrote on a (simulated) robot.
Try this (optional)Move your println into teleopPeriodic(), re-simulate, enable Teleop, and watch it print over and over — that’s the 50×/second loop. Then move it back to teleopInit().
6Save your work to Git10 min

How the team shares code and how you never lose work. Fiddly the first time — that’s normal. Open Terminal → New Terminal.

Tell Git who you are (once):

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Make your first commit:

git init
git add .
git commit -m "Week 1: Hello, Robot"

Push to your own branch (ask your mentor for the repo URL):

git remote add origin <TEAM-REPO-URL>
git branch -M wk1/yourname
git push -u origin wk1/yourname
✅ Checkpoint 4Run git log --oneline and see your commit. Auth error on push? Get the local commit done first — finish the push with a mentor.

🏁 You’re done when…

  • Your project shows BUILD SUCCESSFUL.
  • Your message printed in the simulator.
  • git log shows your first commit.
★

Stretch goals — if you finished early

  1. Open a pull request from wk1/yourname into main (ask a mentor to walk through it — the real team workflow).
  2. A useful loop. In teleopPeriodic(), print a number that counts up using a field at the top of the class:
private int loops = 0;

@Override
public void teleopPeriodic() {
  loops++;
  if (loops % 50 == 0) {              // every ~1 second
    System.out.println("Seconds enabled: " + loops / 50);
  }
}

Why the if? Without it you’d print 50×/second. This prints about once per second instead.

  1. Explore the Sim GUI — find the joysticks panel and NetworkTables view. You can’t break anything.
  2. Be a helper — get a struggling pair to a green checkmark.
